  filtered. The filter remains as a backstop for aliases/regressions.

## ⚠️ ONE REGRESSION I CAUSED AND FIXED — READ THIS

While clearing caches for W4 I ran **`php artisan config:cache`**. That broke the runtime connection:
`RuntimeClient` reads `env('RUNTIME_URL')` / `env('RUNTIME_SECRET')` **directly**, and once Laravel's
config is cached, `env()` outside config files returns null. Result: 12 `RuntimeClient not configured`
errors between 14:00–14:06, and `generate_meta` tasks 2143/2144/2145 failed.

**Fixed:** `config:clear` + fpm reload + worker restart. `isConfigured: YES`, zero errors since 14:20,
roster and W4 guard both re-verified after the fix.

**DO NOT run `php artisan config:cache` on this app** until `RuntimeClient` is migrated to a
`config/services.php` entry. There is a `RuntimeClient.php.bak-envconfig-20260707-194219` showing
someone started that migration and it never landed — the live file still uses `env()`.
**Follow-up candidate:** finish that migration, then config caching becomes safe (and faster).

Also worth knowing: **this app logs to a single `storage/logs/laravel.log`**, not `laravel-DATE.log`.
An earlier check of mine tailed the dated filename and reported "clean" off a file that doesn't exist.
